# Security audit — GenosDB 0.36.0 (September 2026)

**Audited.** GenosDB 0.36.0 — the engine, the published examples and the release chain — with GenosRTC 0.31.2 (transport and signaling) and GenosSRV 0.12.0 (the Fallback Server: gate mirror, relay, governance). Reviewed on 16–19 September 2026 against the built bundles and their sources.

**Method.** A structured audit run under Cloudflare's `security-audit` skill in its quick profile: reconnaissance, one wave of nine hunters over 22 coverage units (surface × trust boundary × attack class), and an independent verifier for every candidate — never the hunter that found it — with a bounded offline reproduction against the real modules for each verdict. Every rejection was then re-read by a second verifier that was not shown the first verdict. The threat model is the one in [SECURITY.md](../../SECURITY.md): any peer may run modified code, the network is hostile, and a peer applies nothing it cannot verify; the twelve boundaries of [CRYPTOGRAPHY.md](../../CRYPTOGRAPHY.md) §12 are decisions, not findings. The private conformance battery — real browsers over real WebRTC, one browser context per peer, a fresh room per test — and the public test vectors were run before and after. In parallel, an independent black-box matrix of 46 cases, built with a different toolchain, attacked the published bundles from a hostile browser and converged on the same engine defect.

**Result.** Four findings, all fixed in [0.36.1](../../CHANGELOG.md) with a test red before each fix. Two candidates disproved — both restated decisions the project had already taken and pinned. Twelve units closed with no candidate. Five units deferred (below). Nothing in signing, verification, key derivation or ordering failed: the four defects sit in one layer, what a value is allowed to carry, and in the demos' rendering.

## What held

The two authorship gates against a modified peer, catch-up and ordering, persistence and cross-tab copies, record envelopes and passkey custody, transport framing and the cellular overlay, signaling and the embedded relay, the release chain, the literal-exposure sweep and a wildcard pass — each closed with concrete checks, several against offline harnesses driving the real modules. In the black-box matrix, 40 of 46 cases held: unsigned operations on all four sync paths, tampering with content, id, identity, address, timestamp and signature, guest writes and deletes, self-escalation, role claims in a bootstrap, demotion, replay of old promotions, ACL variants, a clock run forward, a corpus of invalid signatures, and a sequential revoke of an encrypted record.

## Findings, fixed in 0.36.1

1. **A write collaborator could change a node's policy — high.** The authorship gate judged a non-owner's write by who the author was, never by what the value carried, while a record's owner, collaborator list and envelope table travel inside the value. A collaborator granted only `write` could take the node, grant itself `delete`, or drop the owner's read envelope; and, with no attacker at all, a collaborator returning from a copy that predated a `revoke` re-shipped the revoked reader's envelope under the rotated-away key, so the revoked identity opened everything written after the revocation. Reproduced twice offline and once in a real browser over WebRTC. Fix: on an owned node a non-owner's write applies only if `owner`, `collaborators` and the envelope table equal the receiver's; an existing node without an owner takes one only from a role that could delete it. Three lines of code in each gate. Pinned by gate-battery verdicts and an envelopes case with a partitioned collaborator.
2. **A governance time objective was measured on the subject's own stamp — medium.** Both governance engines compared a node's timestamp — a number its last writer chooses and signs, bounded only in the future — with the clock, so a fresh identity on a modified client backdated its bootstrap and a rule declaring a seven-day wait promoted it in the first cycle. Fix: each engine keeps its own observation of every node's stamp and fires a rule only when it has watched the current stamp for the objective. Five lines in each engine. Pinned by a governance case whose peer runs its clock behind.
3. **The priority flag was accepted from the subject — low.** The resolver's priority path skips last-write-wins for any role-node write carrying `priority: true`, whatever its author, and the gate's subject branch never refused the flag: a subject could regress its own node's clock and let an older self-write erase a superadmin's newer non-role write of that node. Fix: the subject branch refuses the flag; only a superadmin's signature carries it. Zero lines net. Pinned by the gate battery.
4. **Six demos rendered a peer's value as markup — medium.** `kanban`, `infinite-scroll`, `pagination`, `spreadsheet`, `keystrokes` and `gaze-heatmap` interpolated a field another visitor wrote into `innerHTML`, against the rule the examples themselves state: a peer's value renders as text. No session and no key were reachable — the passkey secret is per browsing context — but another visitor's page was. Fix: each site builds its node with `textContent` or escapes the field; an image source is taken only with an `http(s)` scheme. Twelve lines across six files. Pinned by an examples case that writes `<img src=x onerror>` into each room from a second browser context.

## Disproved candidates

- **An authority-written metric on a `user:` node is overwritable by its subject.** True, and the declared contract: the subject rewrites its own node except `role` and `expiresAt`, and the exact sequence is a green case of the gate battery. The residue was a documentation sentence that prescribed a mitigation the engine cannot provide; corrected in 0.36.1.
- **The governance engine re-decides an expired role without its expiry.** True, and the documented stateless design since 0.15.0: an expiry is final until the constitution decides again, and a governance write is that decision. The second verifier signed the engine's own operation with other keys — the subject's, an outsider's — and the gate refused both; only an address the clients list as superadmin can produce it. The proposed fix, executed, re-created the renewal loop 0.15.0 removed. The residue was two documentation sentences that attributed role expirations to the engine; corrected in 0.36.1.

## Not covered

A quick profile is a partial pass by construction. Deferred to a later run: collaborator revocation on plain ACL nodes under a racing write (the encrypted case is finding 1), convergence of owned nodes a collaborator edited last on peers that never held them, the author field a demo names, the demos' CDN includes without integrity attributes, and the demos' shared origin. Out of this run: the native peer (GenosDB-Rust), whose gate needs the policy binding of finding 1 in its own release, and the internals of GenosRTC beyond framing, signaling and the overlay.

## Evidence

Before the run: private battery 76/76, gate battery 87 verdicts, public vectors 98/98 with the bundle's SHA-256 matching the pins. After 0.36.1: private battery 84/84 in 9.9 minutes with no flaky test (eight new cases, every one red before its fix), gate battery 107 verdicts including the browser/server parity check, public vectors 98/98 once the pin of the rebuilt `sm.min.js` is regenerated. Findings and coverage were recorded in the skill's machine-readable ledgers and validated by its schema checkers.
